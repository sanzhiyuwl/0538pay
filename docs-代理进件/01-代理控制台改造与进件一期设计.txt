====================================================
形态（已定 2026-07-28）：独立端，不挂 /console 按角色隔离。
  - 布局：新建 layouts/AgentLayout.vue（沿用后台 UI 设计规范 + ConsoleLayout 侧栏/顶栏风格，

代理端菜单（/agent，一期）：
  /agent                工作台（首页）—— 我的名额余额 / 我的进件数(审核中/成功/驳回) / 我的佣金概览
  /agent/enroll         我的进件 —— 只列自己名下进件单，可代客户发起进件、查状态、

                        → 校验过回显订单信息二次确认 → 确认后原路退还开户费
                        （复用退款基建，退全额不扣手续费）
  /agent/invites        我的邀请码 —— 生成/管理自己的进件邀请链接与二维码、看打开/提交统计、
                        对失效链接一键重发/新建替换（客户无法自助复活，重开入口收敛在这里）
  /agent/quota          我的名额 —— 名额余额、买名额(走收单收款)、名额流水
  /agent/settlement     我的佣金 —— 进件成功后我得的佣金记录、提现(复用现有提现基建，二期可细化)
  /agent/profile        账号设置 —— 改资料/改密码

代理端 REST（需代理登录态，前缀 /api/agent，全部按登录 agent_id 强制过滤）：
  - POST /api/agent/login                       代理登录发 JWT
  - GET  /api/agent/dashboard                   工作台聚合
  - GET/POST /api/agent/enrolls                 我的进件单列表/发起进件（agent_id=自己）
  - POST /api/agent/enrolls/refund              代理手动退款（两步：先查验回显，确认后执行）：
    入参进件申请单号。★退款前逐项强校验，任一不过即拦截并返回明确原因，绝不盲目退：
      a. 单号存在性：查无此单 → 拦"申请单号不存在，请核对"
      b. 归属校验：该单 agent_id ≠ 登录代理 → 拦"该单不属于您，无法操作"（防退错别人的单）
      c. 状态可退：仅【已支付待完善/已驳回】等已实际收款且未退的状态可退；
         待支付(未收款)/已退款(重复退) → 拦并提示对应原因
      c★. 已开通硬锁定（最高优先级，代理端+平台端一律生效，无例外）：
         该单一旦拿到 sub_mchid（status=已完成，商户已真正开通成功）→ 永久锁定不可退，
         拦"商户已成功开通，不支持退款"。防止开通成功后还退款（代理白干/平台亏）。
         wx_sub_mchid 非空即视为已交付，退款接口一律拒绝，平台兜底退也不破此例外。
      d. 收款匹配：该单须有有效收款单号 pay_order_no 且金额>0 → 无款可退则拦
    校验全过 → 回显订单信息（商户名/金额/当前状态）供代理二次确认 → 确认后才原路退全额
    → status=已退款、写 quota_log/settle_log 相应回滚。（幂等：同单重复提交只退一次）
  - GET/POST/PUT /api/agent/invites             我的邀请链接 CRUD（agent_id=自己）
  - GET  /api/agent/quota (+/purchase)          名额余额/流水、买名额
  - GET  /api/agent/settlements                 我的佣金记录
  - PUT  /api/agent/profile /password           改资料/改密码
  ★ 平台端 /api/console/* 管所有代理，代理端 /api/agent/* 只碰自己——两套接口分开，
    共用 service 层但入参强制带 agent_id 隔离。

====================================================
一之二、代理权限设置（可扩展权限体系，2026-07-28 新增）
====================================================
目标：代理能用哪些功能，由平台【逐项开通的权限】决定——平台给某代理开通了哪些
  权限，该代理端就出现哪些菜单/功能、后端就放行哪些接口。核心诉求：权限开通啥、
  代理就有啥。为后续持续加功能预留：新增一个功能只需登记一个【权限点】，平台在
  代理管理里勾选即生效，代理端骨架不用改。

权限模型（单一数据源、可扩展、数据驱动）：
  - 权限点清单（permission key）后端集中登记一份常量清单，每项含
    key / 中文名 / 分组 / 说明，例如（一期起步集，后续按需追加行）：
      · enroll      进件代理：发起/管理特约商户进件   —— 即原 can_enroll
      · acquire     收单代理：收单分润（占位，暂不启用）—— 即原 can_acquire
      · quota       名额钱包：买名额 / 用名额
      · invite      邀请链接：生成/管理进件邀请码与二维码
      · refund      手动退款：代理自助对自己名下单发起退款
      · settlement  佣金结算：查看佣金 / 提现
    （★ 将来加新功能 = 在此清单追加一行 key，别处不用大改。）
  - 代理持有的权限：pay_agent.permissions 存【已开通权限点集合】（JSON 数组或
    逗号分隔 key 串），不再零散新增 can_xxx 布尔字段。
  - can_enroll / can_acquire 收敛：视为权限体系的两个【内置权限点】(enroll/acquire)，
    统一进 permissions 管理。文档早前的 can_enroll/can_acquire 字段语义保留，
    但以 permissions 为准；过渡期如需并存，读取时以 permissions 集合为唯一真值。

平台侧（/console 代理管理）：
  - 开通 / 编辑代理时新增「权限设置」区：按分组列出【全部权限点】，勾选开通。
  - 权限点清单由后端接口返回，前端数据驱动渲染——新增权限点后前端无需改动。

代理侧（/agent）：
  - 登录后随身份下发自己的 permissions；菜单与页面按权限【动态显示】
    （无权限的菜单不渲染）。
  - 后端接口按 permissions【强校验放行】（不只是前端隐藏），无权限调用直接拒绝。
  - ★ 权限与数据隔离正交，两者都要有：permissions 管「能不能用这个功能」，
    登录 agent_id 管「只能看/操作自己名下」。不可用权限替代隔离，也不可用隔离替代权限。

接口：
  - GET  /api/console/agent-permissions   返回权限点清单（key/名称/分组/说明，供勾选）
  - 代理的 permissions 随 POST/PUT /api/console/agents 创建/编辑时一并落库
  - 代理端 GET /api/agent/dashboard（或登录响应）回带当前代理的 permissions 供前端渲染

二、后端模块划分（Go，不碰 PaymentChannel 契约）
====================================================
新增独立业务域，不进渠道 registry / 收单主链 / 收银台 / 插件卡片墙：

internal/submerchant/            特约商户进件域（自研）
  - 复用 internal/channel/wxbase 的：DoRequest(V3请求+签名)、平台证书验签、
    RSA-OAEP 敏感字段加密（encryptUserName 同款，用于 id_card_number/mobile_phone/
    account_number/account_name/contact 等敏感字段）
  - 但【不实现 PaymentChannel】—— 进件是 service，不是渠道

微信进件四接口（照官方，服务商体系）：
  1. 提交申请单   POST /v3/applyment4sub/applyment/
     body: business_info/subject_info/identity_info/bank_account_info/contact_info/
           settlement_info + business_code(服务商自定义唯一编号，驳回可复用覆盖)
     敏感字段加密 + HTTP 头 Wechatpay-Serial
  2. 查询申请单状态 GET /v3/applyment4sub/applyment/business_code/{business_code}
     或 GET .../applyment/applyment_id/{applyment_id}
     状态机：审核中→(待账户验证)→待签约→开通权限中→已完成 / 已驳回
     完成后返回 sub_mchid
  3. 修改结算账号 POST /v3/apply4sub/sub_merchants/{sub_mchid}/modify-settlement
  4. 查询结算账户 GET /v3/apply4sub/sub_merchants/{sub_mchid}/settlement

数据表（GORM，表名 pay_ 前缀对齐项目习惯）：
  pay_agent               代理（id/name/账号/密码bcrypt/联系方式/状态/permissions(已开通权限点集合,
                          JSON数组或逗号分隔key串;含内置 enroll/acquire,替代原 can_enroll/can_acquire)/备注）
                          ★权限体系见「一之二」：权限开通啥代理就有啥，加新功能只需追加权限点 key
  pay_agent_quota         名额钱包（agent_id/balance/累计购买/累计消耗/更新时间）
  pay_agent_quota_log     名额流水（type:purchase/consume/refund, change, before, after, 关联单号）
  pay_submch_enroll       进件申请（进件单号/agent_id/主体类型/资料字段(敏感加密)/path/零售额/
                          收款单号/wx_applyment_id/wx_sub_mchid/status/驳回原因/时间/
                          source(1平台代填/2代理代填/3客户自助)/invite_code）
  pay_enroll_invite       进件邀请链接（code唯一/agent_id/name备注/status(启用/停用/expired)/
                          first_access_at首次打开/expire_at(★锚定终态事件,为空=不倒计时仍有效)/
                          打开数/提交数/创建时间）—— 客户自助进件入口，二维码由前端按 code 生成
                          ★有效期24h【不从打开死算】,锚定终态事件后才起算(可配):
                           待支付超时关单→关单时刻+24h; 已支付后被驳回/退款完成→收到返回时刻+24h;
                           审核中未拿到任何返回→expire_at 保持空,链接一直有效不倒计时
                           (防微信审核拖长误关)。到期自动 expired;客户无法自助复活,
                           重开须代理/平台重新生成并分享。定时任务扫过期置 expired。
  pay_enroll_pricing      计价规则（批发价/零售价/平台分成/代理分成/失败退款规则）—— 存 pay_config 亦可
  pay_enroll_settle_log   进件结算流水（enroll_id/agent_id/代理得/平台得/结算时间/关联收款单号）

分层（对齐项目现有 model/repo/service/handler）：
  model → repo → service（进件业务编排：提交/查状态/结算/退款）→ handler（REST）

REST 接口分两组鉴权：
  A. 后台/控制台（需鉴权）：
     - 邀请链接 CRUD：POST/GET/PUT /api/console/enroll-invites（生成/列表/停启用/删除）
     - 进件单管理、提交微信、查状态、结算、退款（同前）
  B. 公开（免登录，客户自助）：独立路由前缀 /api/public/enroll
     - GET  /api/public/enroll/:code            校验 code(存在/启用/未过期：expire_at 为空或
       未到均视为有效) + 首次打开落 first_access_at + 返回该页所需配置；已过期返回 expired 提示
       已失效。★expire_at 不在这里写——由终态事件(关单/驳回/退款完成)触发时 service 置 now+24h
     - POST /api/public/enroll/:code/captcha     图形/短信验证码（复用项目现有验证码基建）
     - POST /api/public/enroll/:code/submit      提交进件单（校验验证码→敏感字段加密→落库 source=3）
     - GET  /api/public/enroll/query             凭进件单号+手机号查进度
     - POST /api/public/enroll/upload            证件上传（限类型/大小，走现有 /uploads）
     ★ 公开组必须：code 有效性校验、验证码防刷、接口限流、敏感字段加密、不返回内部字段。

四、两条路径的落地（计价可配，价格不写死）
====================================================
★付费时点（已定 2026-07-28）：付费【前置】——进件第一步创建进件单时即要求客户付款，
  付款成功才允许继续填全套资料/提交微信审核。先收钱再干活，避免白填资料/空占名额。
  （唯一例外：代理有名额且约定"名额已含开户费、客户不再单独付"的场景，见路径一说明——
   是否让客户免付由 pay_enroll_pricing 的"路径一客户是否付费"开关控制，默认付。）

创建进件单即付费的落地：
  - 第1步 客户填最基础信息（商户名/联系手机）→ 点"创建进件单"
  - 系统建 pay_submch_enroll，status=待支付(pending_pay)，金额=零售价(读 pricing)
  - 立即调起收款（复用现有收单主链下单/收银台）→ 客户扫码/H5 付款
  - 支付回调确认到账 → status=已支付待完善(paid) → 放行第2步填全套资料/传证件
  - 第2步 提交 → 调微信进件接口 → status=审核中…

路径一（代理预购名额）★资金托管已定：先进平台账，进件成功后平台再分给代理★：
  - 代理买名额 → 走收单收款（复用现有下单）→ pay_agent_quota +N、quota_log(purchase)
  - 客户创建进件单即付零售价（付费前置，同上）→ 进【平台账】，收款单号回填 pay_order_no
  - 进件成功（微信 sub_mchid 到手）→ quota_log(consume) 扣代理 1 名额；
    平台把客户付的这笔【全额分给代理】（平台账过账再转，便于留痕/风控；走 enroll_settle_log
    记一笔代理得全额、平台得 0 的过账，与路径二共用结算流水表）
路径二（代理无名额，商户自付）：
  - 客户创建进件单即付零售价进平台账（付费前置，同上）
  - 进件成功 → enroll_settle_log 结算：代理得一份、平台得一份（比例读 pay_enroll_pricing）
计价：批发价/零售价/分成全部读 pay_enroll_pricing（后台可配），程序不硬编码金额。

★付费前置带出的两条必做规则（否则收了钱活没干=客诉）：
  1. 待支付超时【已定 30 分钟】：创建后 30 分钟未支付 → 自动关单（复用现有超时关单 cron，
     沿用现有订单 30 分钟口径），不占名额、不留脏单。触发关单=终态事件，起算链接 24h。
  2. 已支付后退款：见下"失败/放弃退款"。

失败/放弃退款（已定 2026-07-28：自动退 + 手动申请退 两种触发并存，均原路全额退）：
  - 自动退（无需客户操作）：微信审核失败/被驳回 → 系统收到驳回结果后【自动原路退返】
    客户已付的开户费；退款完成=终态事件，起算链接 24h。
  - 手动申请退（客户主动放弃）：客户已付款但不想做了 → 凭【进件申请单号联系代理】，
    由代理在代理后台 /agent/enroll 拉起手动退款（输入申请单号→校验归属本代理→确认原路退），
    平台后台 /console 也能对任意单发起退款兜底。★代理必须能自助退，不能只有平台能退，
    否则客户找代理退款却退不了。代理退款强隔离：只能退 agent_id=自己 的单。
  - 均复用现有退款基建（channel.Refunder / Refund 原路退款）；退【全额】开户费，不扣手续费。

====================================================
五、进件状态与本地状态映射
====================================================
本地 pay_submch_enroll.status 全量状态机（含付费前置阶段）：
  待支付(pending_pay) —— 已建单未付款，创建即进入；超时未付自动关单
    → 已支付待完善(paid) —— 付款回调确认到账，放行填全套资料
    → 已提交(submitted/审核中) —— 提交微信后
       ↓ 映射微信申请单状态：待账户验证 / 待签约 / 开通权限中
    → 已完成(finished) —— 拿到 sub_mchid，触发扣名额(路径一)或结算(路径二)；
       ★终态且不可退：wx_sub_mchid 非空即锁定，退款接口一律拒绝（已交付）
    → 已驳回(rejected) —— 可改资料复用 business_code 重提，或走退款
  旁支：已关单(closed，待支付超时) / 已退款(refunded，已支付后放弃或驳回退款)
  说明：微信申请单状态（审核中/待账户验证/待签约/开通权限中/已完成/已驳回）只在
    "已提交"之后才有意义；付费前置的 pending_pay/paid 是我方本地阶段，与微信无关。
查状态方式：一期先「手动/定时查询申请单状态」拉取最新；
  （微信也支持公众号通知超管，二期可接）
